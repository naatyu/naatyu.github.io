## Corrections and scope

- Random pivots do not guarantee avoiding quadratic work. All-equal input remains quadratic with strict Lomuto regardless of pivot randomness; three-way equal handling avoids repeated equal-value selection.
- Expected balanced progress does not mean every random partition halves the input. Recursive selection can use O(n) stack in the worst case; iterative in-place selection uses O(1) auxiliary state, excluding a caller-preserving copy.
- Partition routines can return a final pivot rank or a split boundary. Their recursion bounds are not interchangeable.
- Merge-sort bases include zero and one value. Stable merge uses the left source first on equal keys. Quicksort being universally 2–3× faster is removed as an unsupported general claim.
- Python 3.14 added native max-heap operations. Negation remains a compatible technique, not the only current API.
- Top-frequency auxiliary space includes the count map. A returned heap is not a sorted top-k list. Empty selection k=0 differs from a kth-rank query.
- Frontier work separates inspecting empty sources, heapify versus repeated pushes, extraction and retained output. The lab uses repeated pushes to initialize, not bottom-up heapify.
- Lazy physical heap size can exceed logical active size; stale entries and duplicate occurrences require correct accounting.
