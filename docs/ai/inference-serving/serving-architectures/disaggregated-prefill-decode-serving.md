## Summary

Disaggregated serving is an architectural pattern for LLMs that splits the inference process into two physically separate pools: **Prefill** (compute-bound) and **Decode** (memory-bound). This separation eliminates interference between these phases, allowing for independent scaling and optimized hardware utilization.
## Concepts
- **Prefill Phase**: The initial processing of the prompt where all input tokens are processed in parallel.
- **Decode Phase**: The autoregressive generation of output tokens one-by-one.
- **KV Cache**: Key-Value tensors stored to avoid recomputing the attention of past tokens.
- **Arithmetic Intensity**: The ratio of total floating-point operations (FLOPs) to total data movement (bytes).

## 1. The Two Phases of LLM Inference

LLM inference is a tale of two bottlenecks. Traditional colocated serving (running both on the same GPU) forces a compromise between them.

| Feature | Prefill Phase | Decode Phase |
| :--- | :--- | :--- |
| **Bottleneck** | **Compute-Bound** (High arithmetic intensity) | **Memory-Bound** (Low arithmetic intensity) |
| **Operation** | Dense matrix multiplications over the whole prompt. | Loading all model weights to predict a *single* token. |
| **Input** | Large batch of prompt tokens. | Single token (the last one generated). |
| **Hardware Fit** | Optimized for high FLOPS (e.g., H100, TPU). | Optimized for High Bandwidth Memory (HBM). |

### Mathematical Latency Models
- **Prefill Time**: $t_{prefill} = \frac{L_p}{R_p}$ (where $L_p$ is prompt length and $R_p$ is throughput in tokens/sec).
- **Decode Time**: $t_{decode} = \frac{L_d}{R_d}$ (where $L_d$ is output length and $R_d$ is rate in tokens/sec).

---

## 2. The Case for Disaggregation
In traditional serving, **interference** is the primary efficiency killer:
1. **Blocking**: A long prefill request arriving at a GPU can block the decoding steps of 50 other active users, causing "stutters" and high jitter in Time Per Output Token (TPOT).
2. **Underutilization**: Decode phases often leave the GPU's compute cores idle while waiting for memory, whereas Prefill phases saturate compute but are often delayed by decoding queues.

### The Disaggregated Architecture
By splitting these into separate pools:
- **Prefill Nodes** can be packed with high-batch requests to maximize throughput.
- **Decode Nodes** can focus on minimizing latency and maximizing memory bandwidth utilization.
- **Independent Scaling**: If a workload has massive prompts (e.g., RAG), you scale the prefill pool. If it has long generations (e.g., creative writing), you scale the decode pool.

---

## 3. The KV Cache Transfer Challenge
The primary cost of disaggregation is that the **KV Cache** generated by the prefill node must be moved to the decode node before generation can begin.

$$t_{transfer} = L_p \cdot c_{kv}$$
*(where $c_{kv}$ is the per-token transfer cost over the network/interconnect).*

### Mitigation Strategies
- **Fast Interconnects**: Using NVLink or InfiniBand to minimize transfer time.
- **Compressed KV Cache**: Using 4-bit or 8-bit quantization for the cache to reduce the payload size.
- **KV Cache Hiding**: Starting the transfer of earlier layers' KV caches while later layers are still being computed in the prefill node.

---

## 4. Key Performance Metrics

1. **Time To First Token (TTFT)**:
   $$TTFT = t_{decode\_start} - t_a$$
   *In disaggregated systems, TTFT includes queuing, prefill time, and transfer time.*
2. **Time Per Output Token (TPOT)**: The latency between subsequent tokens during the decode phase. Disaggregation keeps this highly stable.
3. **Utilization ($U$):**
   $$U_{pool} = \frac{\sum t_{busy}}{N_{instances} \cdot \text{makespan}}$$

---

## 5. Scheduling & Systems
State-of-the-art systems like **DistServe**, **Splitwise** (Microsoft), and **vLLM** (with experimental support) implement these policies.
- **Earliest-Available-First**: Dispatches requests to the node that will become free soonest.
- **Locality-Aware Scheduling**: Tries to keep decodes on nodes where the KV cache might already reside (in cases of multi-turn conversations).
