## Summary

In long LLM RL programs, self-distillation is not only a model-compression trick. It is a way to preserve progress, reset unstable numerics, transfer gains into a cleaner base policy, and continue the climb from a stronger checkpoint.

## Concepts

- **Self-distillation:** supervised training on traces generated by the model itself or closely related checkpoints.
- **Climb:** a long RL training trajectory focused on a domain such as STEM, coding, or helpfulness.
- **Trace diversity:** variation across prompts, checkpoints, and reasoning trajectories.

## 1. Why self-distill during RL

Long RL climbs can hit problems:

- numeric instability
- stale or narrow policy behavior
- migration to a new pretrained checkpoint
- need to move from prompt-induced behavior to native chat behavior

Self-distillation is a practical reset mechanism:

- collect traces from the RL policy
- train a supervised model on them
- restart RL from the distilled checkpoint

This keeps the useful behavior while cleaning up the optimization state.

## 2. What self-distillation is doing

It is not mainly “compressing” the model into a smaller one.

Instead, it is:

- re-anchoring the policy into a stable supervised objective
- preserving useful trajectory patterns
- making the next RL stage easier to optimize

So in this setting, self-distillation acts like a continuation operator between climbs.

## 3. Useful findings from the MAI report

### O(1M) good traces are often enough

You do not necessarily need a giant trace corpus to preserve teacher performance.

### Later traces matter more

Very early traces in the climb can drag the student backward.

Using traces from stronger later checkpoints is generally better.

### Diversity matters

For a fixed token budget:

- more prompt diversity is usually better than more traces per prompt

### Successful traces are often enough

If the run already produced plenty of successful rollouts, training on successful traces only can work well.

## 4. Why not just use the final checkpoint

Using traces only from the very last RL checkpoint can be weaker than sampling from multiple strong checkpoints.

A plausible reason is that multiple strong checkpoints provide:

- broader behavioral diversity
- less collapse onto one narrow policy style

That diversity helps when RL resumes.

## 5. Self-distillation for failure recovery

This is one of the most practical uses.

Sometimes an RL run degrades or collapses due to numerics or off-policy mismatch. Rolling back to an older checkpoint may not be enough, because the problem may already be embedded earlier in the weights.

Self-distillation can recover progress by:

- extracting the useful responses
- rebuilding a stable policy through SFT
- restarting from there

## 6. Long-context forgetting

One subtle risk is that self-distillation can forget long-context behavior.

This happens especially when:

- RL traces were generated with shorter maximum lengths
- the self-distillation dataset underrepresents long-context behavior

A practical mitigation is:

- mix in mid-training or long-context data during self-distillation

This preserves the longer-context capabilities while still transferring the RL behavior.

## 7. Practical role in an RL program

Self-distillation is useful for:

- prompt-to-chat migration
- instability recovery
- transferring gains across model generations
- consolidating multiple specialist teachers

So it should be viewed as part of the RL training pipeline, not just a one-off trick.
