## Summary

Cross-Entropy Loss measures how well a predicted probability distribution matches a target distribution. It is one of the main objectives for classification tasks and is closely related to [Kullback-Leibler Divergence](/atlas/math/probability/kullback-leibler-divergence).
## Concepts
- **Target Distribution:** The true probability distribution we want the model to match.
- **Predicted Distribution:** The model output after applying a probability-normalizing function such as Softmax.
- **Entropy:** A measure of uncertainty in a distribution. See [Entropy](/atlas/math/probability/entropy).
- **Kullback-Leibler Divergence:** A divergence that compares two distributions and is used to derive cross-entropy. See [Kullback-Leibler Divergence](/atlas/math/probability/kullback-leibler-divergence).

## Content

### What It Represents
Cross-entropy represents the **average coding cost** of the true distribution when it is encoded with a model distribution.

In practice, it tells you:
- how surprised the model is by the true outcomes
- how well the predicted probabilities match the target probabilities
- how expensive it is to use the wrong distribution to describe the data

If the model assigns high probability to the correct outcome, cross-entropy is low. If it assigns low probability to the correct outcome, cross-entropy is high.

### Mathematical Definition
For two discrete distributions $P$ and $Q$, the cross-entropy of $P$ relative to $Q$ is:

$$H(P, Q) = -\sum_i P(i)\log Q(i)$$

If $P$ is the true distribution and $Q$ is the model prediction, then minimizing cross-entropy encourages $Q$ to place high probability mass on the outcomes favored by $P$.

### Relationship to Entropy and KL Divergence
Cross-entropy can be decomposed as:

$$H(P, Q) = H(P) + D_{KL}(P\|Q)$$

This is useful because:
- $H(P)$ is fixed for the dataset
- minimizing cross-entropy is equivalent to minimizing [Kullback-Leibler Divergence](/atlas/math/probability/kullback-leibler-divergence) from the target distribution

### Intuition
Cross-entropy penalizes confident wrong predictions very strongly.
- If the model assigns low probability to the true class, the loss becomes large.
- If the model assigns high probability to the true class, the loss becomes small.

### Multi-Class Classification
For single-label multi-class classification, the pipeline is usually:

1. Compute logits
2. Apply Softmax to get a probability distribution
3. Compute cross-entropy against the one-hot target

If the target is one-hot encoded, the loss reduces to:

$$L = -\log q_{y}$$

where $q_y$ is the predicted probability for the correct class.

### Binary Case
Binary Cross-Entropy is the two-class special case of cross-entropy when the target distribution is Bernoulli. See [Binary Cross-Entropy Loss](/atlas/ai/training/losses/binary-cross-entropy-loss).

### Numerical Stability
In practice, cross-entropy is usually computed from logits directly rather than from probabilities, because combining Softmax and log into one operation is more stable. This avoids underflow when probabilities become extremely small.

### Use Cases
- **Classification**: Standard objective for image, text, and tabular classifiers.
- **Language Modeling**: Next-token prediction in decoder-only transformers.
- **Distillation**: Matching student predictions to a teacher distribution.

### Distillation View

When the target is one-hot, cross-entropy reduces to:

$$
L=-\log q_y
$$

When the target is a teacher distribution $p_T$, the loss becomes:

$$
L_{\text{distill}}
=
-
\sum_i p_T(i)\log q_i
$$

This is still cross-entropy, but the target contains more information than a hard label. It can express that several alternatives are plausible, not only which one was annotated as correct.

## Coding-Theoretic Derivation

This note uses the convention:

- $P$ is reality, the data distribution, or the teacher;
- $Q$ is the model distribution, code, or student.

If a code is optimized for $Q$, the ideal length assigned to outcome $i$ is:

$$
\ell_Q(i)=-\log_2 Q(i).
$$

When outcomes actually arrive according to $P$, the expected code length is:

$$
\mathbb{E}_{i\sim P}[\ell_Q(i)]
=
-\sum_iP(i)\log_2Q(i)
=
H_2(P,Q).
$$

Cross-entropy therefore answers:

> How efficiently does a code designed around $Q$ compress data generated by $P$?

The order matters. $P(i)$ determines how often an event occurs, while $Q(i)$ determines how expensive it is under the chosen code.

### Mismatched-code example

Suppose a code was designed for:

$$
Q=(1/2,1/4,1/8,1/8),
$$

giving ideal code lengths:

$$
(1,2,3,3)\text{ bits}.
$$

Reality then changes to:

$$
P=(1/8,1/8,1/4,1/2).
$$

Continuing to use the old code costs:

$$
H_2(P,Q)
=
\frac18(1)+\frac18(2)+\frac14(3)+\frac12(3)
=2.625\text{ bits/symbol}.
$$

The optimal code for $P$ costs only:

$$
H_2(P)=1.75\text{ bits/symbol}.
$$

The mismatch wastes:

$$
2.625-1.75=0.875\text{ bits/symbol},
$$

which is $D_{\mathrm{KL}}(P\|Q)$.

## Why the Minimum Occurs at the True Distribution

Because:

$$
H(P,Q)=H(P)+D_{\mathrm{KL}}(P\|Q)
$$

and:

$$
D_{\mathrm{KL}}(P\|Q)\geq0,
$$

we have:

$$
H(P,Q)\geq H(P).
$$

For fixed $P$, cross-entropy reaches its minimum when $Q=P$ on the support of $P$. The minimum $H(P)$ is irreducible uncertainty; the gap above it is model mismatch.

This is why cross-entropy is a principled objective rather than merely one of many decreasing penalties that could be applied to the correct-class probability.

## Why the Loss Is Logarithmic

Suppose an alphabet has at least three possible outcomes and the loss for observed outcome $i$ depends locally only on the probability assigned to it:

$$
L(Q,i)=F(Q(i)).
$$

The expected loss is:

$$
\mathcal{R}(Q;P)=\sum_iP(i)F(Q(i)),
$$

subject to:

$$
\sum_iQ(i)=1.
$$

Require that, for every interior target distribution $P$, the unique minimum occurs at $Q=P$. With a Lagrange multiplier $\lambda$, stationarity at $Q=P$ gives:

$$
P(i)F'(P(i))+\lambda=0.
$$

The same $\lambda$ applies to every component, so under this differentiable local-loss setup:

$$
qF'(q)=\text{constant}.
$$

Therefore:

$$
F'(q)=-\frac{k}{q}
$$

for some $k>0$, and integration gives:

$$
F(q)=-k\log q+C.
$$

Up to scale and an additive constant, the negative logarithm is forced by the requirement that honest probabilities minimize expected **local** loss under these assumptions. The binary case admits exceptions, and other proper scoring rules exist when the loss can depend on the whole predicted distribution rather than only the probability assigned to the observed event.

## Why One-Hot Training Is Still Cross-Entropy

For a single example with class $y$, the target is one-hot and the loss reduces to:

$$
\mathcal{L}=-\log Q(y).
$$

The full cross-entropy appears after averaging repeated observations. If labels are sampled from the conditional distribution $P(\cdot\mid x)$, then:

$$
\mathbb{E}_{y\sim P(\cdot\mid x)}[-\log Q(y\mid x)]
=
H\left(P(\cdot\mid x),Q(\cdot\mid x)\right).
$$

Each hard label is one Monte Carlo sample from the underlying target distribution. The empirical dataset average estimates population cross-entropy.

## Language-Model Pretraining as Compression

For a token sequence $x_{1:T}$:

$$
Q_\theta(x_{1:T})
=
\prod_{t=1}^{T}Q_\theta(x_t\mid x_{<t}).
$$

Taking negative logs turns the product into an additive sequence cost:

$$
-\log Q_\theta(x_{1:T})
=
-\sum_{t=1}^{T}\log Q_\theta(x_t\mid x_{<t}).
$$

The standard pretraining loss averages this over non-masked tokens:

$$
\mathcal{L}_{\mathrm{LM}}
=
-\frac1T\sum_{t=1}^{T}\log Q_\theta(x_t\mid x_{<t}).
$$

This has three equivalent readings:

- negative log-likelihood per token;
- average surprise under the model;
- average code length under a model-derived code.

With natural logarithms the unit is nats per token. Convert to bits per token using:

$$
\mathrm{BPT}=\frac{\mathcal{L}_{\mathrm{nats}}}{\ln2}.
$$

Perplexity is:

$$
\mathrm{PPL}=\exp(\mathcal{L}_{\mathrm{nats}})=2^{\mathrm{BPT}}.
$$

Lowering pretraining cross-entropy is therefore mathematically equivalent to improving the model-induced compressor on the data distribution.

## Cross-Entropy Versus KL in Distillation

For a fixed teacher $P_T$ and student $Q_S$:

$$
D_{\mathrm{KL}}(P_T\|Q_S)
=
H(P_T,Q_S)-H(P_T).
$$

The teacher entropy $H(P_T)$ does not depend on student parameters. Consequently, teacher-to-student cross-entropy and forward KL have:

- the same student gradients;
- the same optimum;
- loss values differing only by a teacher-dependent constant.

This assumes the same distributions and temperature are used. Reverse KL,

$$
D_{\mathrm{KL}}(Q_S\|P_T),
$$

is a different objective because the student supplies the expectation weights.

## Gradient with Softmax Logits

Let:

$$
Q(i)=\frac{e^{z_i}}{\sum_je^{z_j}}.
$$

For target distribution $P$:

$$
\frac{\partial H(P,Q)}{\partial z_i}=Q(i)-P(i).
$$

The gradient has a clean interpretation: increase logits where the model assigns too little probability and decrease them where it assigns too much.

## Practical Details

- **Use logits directly.** Framework cross-entropy functions fuse log-softmax and negative log-likelihood for numerical stability.
- **Zero probability is catastrophic.** If $P(i)>0$ but $Q(i)=0$, cross-entropy is infinite.
- **Log base sets the unit.** Base 2 gives bits; the natural log gives nats.
- **Changing log base rescales gradients.** It preserves the optimum but interacts with the learning rate and gradient clipping.
- **Label smoothing changes the target.** It replaces the one-hot $P$ with a softer distribution.
- **Reduction matters.** Token-, sequence-, and batch-averaged losses weight variable-length examples differently.
